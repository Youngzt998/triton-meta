# EXAMPLE OF A REJECTED REPORT -- not an open finding

This is a frozen copy of a report the review **rejected**. It is kept here only
as a worked example of one rejection class, so a reader of `bug-report/` can
judge the filtering. Everything below the line is the automatic text the fuzzing
line wrote; **none of it has been corrected**, including any statement this
banner contradicts.

**Criterion: A2** -- an uninitialised read by the test kernel, not a compiler
difference.

**The measurement that settled it:** read the kernel source in the report. The
local fragment `a_fp32_local` is allocated and **never written**, and the input
buffer `a` is never read at all; both arms then copy those uninitialised
registers straight to `a_out`. So all **2048 of 2048** "differing" elements are
garbage registers. The report's own `candidate self-consistent across repeats:
False` says the candidate build does not even agree with itself between runs.

**Why the automatic gates missed it, which is the real lesson.** A2's stated
test is the heap shift, and here the heap shift came back *difference still
present*; the exact-integer control also came back *still differs*, which
section 2 of `REVIEW-CRITERIA.md` lists as a **keep** signal. Both are blind to
this bug: the heap shift perturbs the GPU allocator, and an uninitialised
**register** is not memory. A label is evidence, never a verdict.

Corpus kernel `cap_7fd65a04c9705768`
(`testing/python/layout/test_tilelang_layout_fused_replicate.py`). It produced
this same false positive three times -- `HIT-0011`, `HIT-0047`, `HIT-0077` --
after which the line added an uninitialised-local scan on the reference side and
dropped the kernel from the corpus.

**The repro command in this report no longer runs.** After the third false
positive from this kernel the line dropped `cap_7fd65a04c9705768` from the
corpus, in both rounds, so `tlfz.repro` cannot load it any more. That is
deliberate and it is the right outcome: the kernel is undefined behaviour, so
there is nothing to compare. The evidence that settles the rejection is the
kernel source printed in the report below, which needs no run.

Expected output: `BIT DIFFERENCE` with the numbers above.  The script compiles
the kernel twice (stock pipeline, then the stock pipeline minus the pass under
test), fills every tensor parameter -- inputs *and* outputs -- with identical
deterministic content on both sides, runs both, and compares every parameter
bit for bit.

`TILELANG_DISABLE_CACHE=1` is mandatory and is set by `env.sh`: TileLang's
kernel cache key does not cover a re-registered pass pipeline, so with the
cache on you get the previous variant's binary back.
