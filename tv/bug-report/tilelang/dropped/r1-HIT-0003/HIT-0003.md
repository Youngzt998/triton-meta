# EXAMPLE OF A REJECTED REPORT -- not an open finding

This is a frozen copy of a report the review **rejected**. It is kept here only
as a worked example of one rejection class, so a reader of `bug-report/` can
judge the filtering. Everything below the line is the automatic text the fuzzing
line wrote; **none of it has been corrected**, including any statement this
banner contradicts.

**Criterion: B1 + B2** -- a deliberate, performance-motivated numeric change,
confirmed by the exact-integer control.

**The measurement that settled it:** re-ran the same pair with integer-valued
inputs (`--mode intvalued`, an fp32 accumulator provably exact below 2^24):
**NO DIFFERENCE**. When evaluation order cannot matter, the two arms agree, so
the difference *is* evaluation order.

**What the licence is.** `tl.disable_wgmma` makes `T.gemm` select the `mma`
tensor-core instruction instead of `wgmma` (`src/cuda/op/gemm.cc`, `AllowWgmma`
/ `SelectInst`) and also changes the warp partition. Different instruction,
different warp split, therefore a different fp32 summation order -- exactly the
licence B1 names.

**Why this example is worth keeping: it is gross.** **1047889 of 1048576**
elements differ, max 3191955456 ulp, max absolute difference 110.56. "Almost
every element is wrong by a lot" is *not* evidence of a bug. The mirror of
section 3 (`"the difference is tiny" is never a reason to reject`) also holds:
"the difference is huge" is never a reason to keep.

**Re-verified by the reviewer, 2026-08-20**, on the round-2 harness (which keeps
its own copy of the same corpus, so round 1 was not touched). The difference
reproduces exactly as reported -- 1047889 of 1048576, max ulp 3191955456, max
abs 110.5625, first element `-326141.5` against `-326166.5625` -- and
`--mode intvalued` gives `NO DIFFERENCE` on **3 of 3** seeds tried (106, 107,
108).
