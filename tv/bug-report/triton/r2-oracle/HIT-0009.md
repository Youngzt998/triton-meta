# HIT-0009: `--tritongpu-coalesce` is not idempotent on `bch:rwkv_ka_fusion_kernel_a1a6115c`
Verdict: CONFIRMED
Oracle:  O2 (pass P versus P;P)
Arch:    generic
Line:    r2-oracle
Culprit: `--tritongpu-coalesce`  (class: layout)
SMT verdict: TODO (reviewing agent)

Summary: starting from the same TTGIR, applying the pass **once** and applying
it **twice** produce cubins whose outputs differ bit for bit on the same input,
with the same compile options. Applying a pass twice is a legal state -- the
real TTGIR pipeline already runs `remove-layout-conversions` three times -- so
the second application should be a no-op on the semantics. That is the whole
claim: a bit difference between two compilations. No judgement about whether it
is a compiler bug is made here; the labels carry the material for that.

## Labels

* oracle: O2 (pass P versus P;P, same TTGIR, same input)
* pass-class: layout
* heap shift: survives
* still differs with small whole-number inputs and a computed value differs, so reassociation of an fp32 sum does not explain it
* ndiff/total: 76/14679616
* max_abs_diff: 0.0, max_ulp: 0
* layout-reorders-reduction (the kernel contains a tt.dot or tt.reduce)
