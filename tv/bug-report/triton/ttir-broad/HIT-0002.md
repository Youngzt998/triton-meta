# HIT-0002: ind::triton_for_fused_1_a94716eb miscompiles under `--triton-reorder-broadcast`
Verdict: CONFIRMED
Arch:    generic
Culprit: --triton-reorder-broadcast
Arm:     B

Summary: the kernel `triton_for_fused_1_a94716eb` is compiled twice from the *same* root TTIR.
The only difference is that the candidate side runs `--triton-reorder-broadcast` first.
Both sides then go through the production make_ttgir, then make_llir / make_ptx / make_cubin -- the identical code. On the same inputs,
in the same device buffers, the two builds write different bits.


Expected output: `MISMATCH` and the first differing element. A fixed compiler
prints `identical on all N draws`.

The `input IR -> output IR` pair on its own, no GPU needed:

```bash
triton-opt artifacts/HIT-0002/reference.ttir --triton-reorder-broadcast -o /tmp/HIT-0002.cand.ttir
```

## Determinism evidence

* corpus pre-screen: 3 runs per input profile on 3 profiles, both lowering
  arms, all bit-identical -- otherwise the kernel would have been dropped;
* at triage: reference side 3/3 self-identical, candidate side 3/3
  self-identical, reference-vs-candidate mismatch reproduced 3/3;
* both sides run on the *same* device buffers at the same addresses
  (fill -> snapshot -> run reference -> read -> restore -> run candidate),
  so an out-of-bounds read cannot make them differ by accident.

## Why this is NOT an expected numerics change

The reference side runs **zero** TTIR passes and the candidate runs
`--triton-reorder-broadcast`. Those passes are canonicalization, CSE, DCE, code motion and
structural rewrites; none of them is licensed to change a floating-point
result. Everything below the TTIR is the identical code on both sides.
The by-design numerics gate did not fire: the only pass in this build that is documented to change FP results at the TTIR level is --triton-combine (Combine.cpp: CombineDotAddFPattern folds an add into the dot accumulator; CombineBroadcastMulReducePattern turns a reduction into a tt.dot), and it is either not in the minimal set or this kernel has no tt.dot / tt.reduce.
