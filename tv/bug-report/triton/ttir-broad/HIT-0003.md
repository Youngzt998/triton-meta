# HIT-0003: bench::_conv_transpose2d_stride2_pad1_3x3_kernel_312550c9 miscompiles under `--triton-combine`
Verdict: needs-review
Arch:    generic
Culprit: --triton-combine
Arm:     A

Summary: the kernel `_conv_transpose2d_stride2_pad1_3x3_kernel_312550c9` is compiled twice from the *same* root TTIR.
The only difference is that the candidate side runs `--triton-combine` first.
Both sides then go through --convert-triton-to-tritongpu, then make_llir / make_ptx / make_cubin -- the identical code. On the same inputs,
in the same device buffers, the two builds write different bits.
Gate note: --triton-combine may rewrite tt.dot/tt.reduce/tt.dot_scaled by design (Combine.cpp: CombineDotAddFPattern / CombineBroadcastMulReducePattern); this kernel already gives different results under the minimal vs the production lowering of the same TTIR, i.e. its float result is layout sensitive

## Determinism evidence

* corpus pre-screen: 3 runs per input profile on 3 profiles, both lowering
  arms, all bit-identical -- otherwise the kernel would have been dropped;
* at triage: reference side 3/3 self-identical, candidate side 3/3
  self-identical, reference-vs-candidate mismatch reproduced 3/3;
* both sides run on the *same* device buffers at the same addresses
  (fill -> snapshot -> run reference -> read -> restore -> run candidate),
  so an out-of-bounds read cannot make them differ by accident.

## Why this is NOT an expected numerics change

The reference side runs **zero** TTIR passes and the candidate runs
`--triton-combine`. Those passes are canonicalization, CSE, DCE, code motion and
structural rewrites; none of them is licensed to change a floating-point
result. Everything below the TTIR is the identical code on both sides.
The by-design gate DID fire here: --triton-combine may rewrite tt.dot/tt.reduce/tt.dot_scaled by design (Combine.cpp: CombineDotAddFPattern / CombineBroadcastMulReducePattern); this kernel already gives different results under the minimal vs the production lowering of the same TTIR, i.e. its float result is layout sensitive -- so this is filed as needs-review, not as a confirmed bug.
