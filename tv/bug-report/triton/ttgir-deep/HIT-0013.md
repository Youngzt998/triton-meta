# HIT-0013: remove-layout-conversions-2, remove-layout-conversions-3 changes results on attn
Verdict: needs-review
Arch:    hopper-only
Summary: Two compilations of the same kernel that differ only in the TTGIR
pass set produce different bits.  Reference = the production sm_90 pipeline
with `remove-layout-conversions-2, remove-layout-conversions-3` removed; candidate = the full production
pipeline.  Bisected culprit set: `remove-layout-conversions-2, remove-layout-conversions-3` (groups: ['layout', 'layout']).
168 of 512 output elements differ;
largest absolute difference 1.9073486328125e-06.

## Reproduction manual

```bash
source /home/youngzt/fuzz/ttgir-deep/env.sh
python -m harness.repro --family attn --cfg '{"dt": "fp16", "M": 512, "N": 512, "BM": 64, "D": 64, "NS": 2, "WS": 0, "W": 4}' --drop '["remove-layout-conversions-2", "remove-layout-conversions-3"]' --dist randn --seed 2127804394
```

Expected output: `MISMATCH` plus the first differing element.

## Pass pipeline: reference vs candidate
Both sides run the real `CUDABackend.make_ttgir` step list for `cuda:90`
(rebuilt step by step in `harness/pipeline.py`).  The candidate runs all of
it.  The reference runs the same list with these steps removed:

```
  - remove-layout-conversions-2
  - remove-layout-conversions-3
```

After TTGIR the two sides are byte-identical code paths: both are written to a
`.ttgir` file and handed to `triton.compile`, which skips every stage up to and
including `ttgir`, so `make_llir` / `make_ptx` / `make_cubin` are the same.

## Why this is NOT an expected numerics change
Groups of the culprit passes: ['layout', 'layout'].
None of the culprit passes is in the numerics-changing group (accelerate-matmul, f32-dot-tc, optimize-thread-locality, optimize-accumulator-init, tmem-load-reduce).  They only move data, change layouts, schedule, or lower to hardware, so the per-element arithmetic and its order should be untouched.
