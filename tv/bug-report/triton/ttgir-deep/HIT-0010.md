## Pass pipeline: reference vs candidate
Both sides run the real `CUDABackend.make_ttgir` step list for `cuda:90`
(rebuilt step by step in `harness/pipeline.py`).  The candidate runs all of
it.  The reference runs the same list with these steps removed:

```
  - hopper-warpspec
  - optimize-dot-operands-2
  - remove-layout-conversions-1
  - reorder-instructions
```

After TTGIR the two sides are byte-identical code paths: both are written to a
`.ttgir` file and handed to `triton.compile`, which skips every stage up to and
including `ttgir`, so `make_llir` / `make_ptx` / `make_cubin` are the same.

## Why this is NOT an expected numerics change
Groups of the culprit passes: ['layout'].
None of the culprit passes is in the numerics-changing group (accelerate-matmul, f32-dot-tc, optimize-thread-locality, optimize-accumulator-init, tmem-load-reduce).  They only move data, change layouts, schedule, or lower to hardware, so the per-element arithmetic and its order should be untouched.
